# Folio frontend verification — 2026-11-10

## Delivered

Next.js App Router + React + TypeScript, a light glass workspace with document upload, document-grounded
Q&A, direct chat, source inspection and document removal. Three panels adapt into a vertical mobile layout.
Replacement/removal require confirmation. Empty/loading/error/no-answer states are explicit. No placeholder
answers or invented progress percentages are shown. Source passages are rendered as plain text.

The narrowly scoped same-origin proxy forwards multipart requests and backend statuses, bounds request
bodies, and keeps the Docker backend hostname on the server. Existing Mac and Windows launchers now start
the frontend alongside the backend, database and model services. The backend API contract is unchanged.

## Validation

- Production `next build`, TypeScript checks and Prettier formatting checks passed.
- **10 Playwright browser tests passed** in real local Chrome. Automated browser API responses are stubbed;
  a separate HTTP fake-upstream check exercises the actual Next proxy, multipart boundaries, response status
  preservation, unknown route restrictions and the request body cap.
- Browser checks cover widths **360, 390, 768, 1024, 1440 and 1920 px** without horizontal page overflow.
- Axe WCAG A/AA automated checks passed for the initial workspace. This is not a full accessibility certification.
- **104 backend tests passed** with real PostgreSQL and OCR enabled; model responses are mocked in that suite.
- Production dependency audit reported no known vulnerabilities at the time checked.
- The one-command Docker startup reached healthy frontend, backend, database and Ollama services.

## Real end-to-end smoke

Using the built frontend at `http://127.0.0.1:3000`, real FastAPI, real Ollama and real pgvector:

1. Refused to overwrite a pre-existing document (the smoke requires an empty library).
2. Clicked **Try the sample document**, which uploaded the existing fictional company handbook.
3. Asked: **How much can I claim for travel expenses?**
4. Received HTTP 200 with `found=true`, citation `chunk-2`, and the answer:
   “Client-visit travel expenses are reimbursed at actual cost, up to THB 500 per day. Receipts are required.”
5. Opened the source panel, including page 1 and the original supporting passage.
6. Captured desktop/mobile screenshots, then removed only the document created by the smoke.
7. No browser page exceptions were observed.

Screenshots in `docs/screenshots/` use that real response and the public fictional handbook, not private data.

## Current limits

One indexed document at a time, as in the backend. Displayed conversation history is tab-local and earlier
messages are not sent as model context; each question is independent. No authentication or public deployment
is included. OCR limits and factual-grounding limitations still apply. Local CPU inference can be slow.
The browser tests and screenshot review were performed on macOS; Windows launcher checks run in CI.
