ENDPOINT 01 / 06

GET /api/v1/health

API ยังตอบสนองอยู่ไหม?

ตรวจ liveness ของ FastAPI เท่านั้น ไม่มีการเรียก service ภายนอก

สิ่งที่ควรเข้าใจ

  • ไม่เช็ก PostgreSQL, Ollama หรือว่าโมเดลพร้อมใช้งานหรือไม่
  • ตอบ 200 ได้ แม้ฐานข้อมูลหรือ Ollama จะใช้งานไม่ได้
  • ใช้สำหรับ liveness; ยังไม่มี readiness endpoint แยก

TRACE TO CODE

backend/app/routes/health.py → health()

ENDPOINT 02 / 06

POST /api/v1/documents

เอกสาร → ข้อความ → vectors

รับ multipart file แล้ว index ให้เสร็จก่อนตอบกลับ เส้นทางอ่านไฟล์ในภาพย่อการวนซ้ำทีละหน้า

สิ่งที่ควรเข้าใจ

  • PDF: ไม่เกิน 50 หน้า / 50,000 ตัวอักษร; ไม่รับ PDF เข้ารหัส
  • OCR เฉพาะหน้าที่ไม่มีข้อความ รวมหน้าว่างไม่เกิน 5 หน้า; ตรวจงบเวลา 120 วินาทีก่อนเริ่มแต่ละหน้า ไม่ใช่ hard deadline
  • เก็บ page และ extraction_method=direct|ocr ไปกับแต่ละ chunk; chunk ไม่ข้ามหน้า
  • ปัจจุบันมีเอกสารครั้งละหนึ่งชุด: upload สำเร็จแทนเอกสารเดิม แต่ parse/OCR/embed/transaction ล้มเหลวจะรักษาเอกสารเดิม
  • สถานะหลัก: 413 ไฟล์ใหญ่, 415 นามสกุลไม่รองรับ, 422 parse/OCR/input ไม่ผ่าน, 502 embeddings ไม่ถูกต้อง, 503 Ollama/DB error, 504 embedding timeout
  • ปิด upload file ใน finally; ไม่เก็บไฟล์ PDF ต้นฉบับไว้สำหรับเปิดย้อนดู

TRACE TO CODE

routes/documents.py → prepare_document()
services/parsing.py → parse_document() / parse_pdf()
services/ocr.py → extract_page_text()
services/ingestion.py → ingest_pages()
storage/postgres.py → replace_chunks()

ENDPOINT 03 / 06

GET /api/v1/documents

ดูว่ามีเอกสารอะไรถูก index อยู่

อ่าน metadata และจำนวน chunks ไม่ต้องเรียกโมเดลหรือโหลด embeddings ทั้งหมด

สิ่งที่ควรเข้าใจ

  • get_documents() ใช้ LEFT JOIN จึงคืน metadata ได้แม้เอกสารนั้นไม่มี chunks
  • ไม่มีเอกสาร → 200 []; DB error → 503
  • ไม่ส่งข้อความ chunks, vectors หรือไฟล์ต้นฉบับกลับมา; route แบบ def ใช้ thread pool ของ FastAPI

TRACE TO CODE

routes/documents.py → list_documents()
storage/postgres.py → get_documents()
api_docs/api_docs.py → DocumentSummary

ENDPOINT 04 / 06

DELETE /api/v1/documents/{document_id}

ลบเอกสารและข้อมูลที่ผูกอยู่

ตรวจ UUID ก่อนเข้า DB และใช้ foreign-key cascade ลบ chunks กับ embeddings ตามเอกสาร

สิ่งที่ควรเข้าใจ

  • UUID ไม่ถูกต้อง → ไม่เรียก DB และ route ตอบ 404
  • UUID ถูกต้องแต่ไม่มีแถว → 404; ลบสำเร็จ → 204 ไม่มี JSON body
  • ON DELETE CASCADE ลบ chunks และ vectors ไปด้วย; DB error → 503
  • หลังลบเอกสารสุดท้าย การเรียก questions จะตอบ 409 ให้ upload ก่อน

TRACE TO CODE

routes/documents.py → remove_document()
storage/postgres.py → delete_document()
infra/postgres/schema.sql → ON DELETE CASCADE

ENDPOINT 05 / 06

POST /api/v1/questions

ถามแบบมีเอกสารอ้างอิง (RAG)

ค้นข้อมูลก่อนสร้างคำตอบ และตรวจรูปแบบกับ citation IDs โดยไม่ได้ตรวจความจริงของคำตอบอย่างอิสระ

สิ่งที่ควรเข้าใจ

  • Request: question ยาว 1–2,000 ตัวอักษร และ top_k 1–10 (default 3); ข้อความว่างหลัง trim → 422
  • SQL ใช้ <=> cosine distance เรียงใกล้สุดก่อน; score = 1 - distance ไม่ใช่ confidence และอาจติดลบ
  • ตรวจ embedding model ภายใน read-only repeatable-read transaction เดียวกับ search; model เปลี่ยน → 409
  • LLM คืน AnswerDraft; ตรวจ JSON, answer/citations consistency และอ้างอิงเฉพาะ IDs ที่ค้นได้ ลองใหม่เฉพาะ validation failure รวมสูงสุด 2 ครั้ง; ยังไม่ผ่าน → 502
  • ถ้า draft answer ว่างและ citations ว่าง → found=false, คำตอบ “ไม่พบข้อมูลในเอกสาร”; ยังตอบ 200 พร้อม sources ที่ค้นได้
  • ไม่มีเอกสารหรือถูกลบระหว่างทาง → 409; DB/Ollama error → 503; Ollama timeout → 504
  • sources คือ chunks ที่ retrieve ทั้งหมด ไม่ใช่เฉพาะ chunk ที่ LLM อ้าง; การมี citation ที่ถูก ID ยังไม่รับประกัน factual accuracy

TRACE TO CODE

routes/questions.py → ask_document()
services/ollama.py → embed_texts()
storage/postgres.py → search_chunks()
services/generation.py → answer_with_sources()
schemas/schemas.py → AnswerDraft / GroundedAnswer

ENDPOINT 06 / 06

POST /api/v1/chat

คุยกับโมเดลโดยไม่ใช้เอกสาร

ส่งคำถามเข้า LLM โดยตรง ต่างจาก questions ตรงที่ไม่มีขั้น retrieval หรือ citations

สิ่งที่ควรเข้าใจ

  • ไม่เรียก PostgreSQL, pgvector, embedding model หรือ OCR
  • ไม่คืน sources, citation_ids หรือ found; ไม่มี conversation history ใน request นี้
  • คำถามว่าง → 422; คำตอบ invalid → 502; Ollama error → 503; timeout → 504
  • ไม่มี structured-answer retry แบบ questions และคำตอบไม่ได้ grounded กับเอกสาร

TRACE TO CODE

routes/chat.py → chat()
services/ollama.py → generate_answer()
schemas/http.py → ChatRequest / ChatResponse
